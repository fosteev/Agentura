# Параллельная работа в worktree

Используй только по явной просьбе о параллельной работе, отдельном worktree или изоляции. Нужны готовый план/roadmap, целевая ветка и список предполагаемо изменяемых файлов. Если две задачи меняют один модуль, конфигурацию, роутер или другой горячий файл — запускай их последовательно: worktree конфликт не отменяет.

1. Проверь `git status`, текущую ветку и `git worktree list`. Чужие worktree и незакоммиченные файлы не трогай.
2. Сверь предполагаемые файлы с активными worktree. Пересечение кода — стоп; пересечение только roadmap или документации допустимо, но его надо зафиксировать.
3. Создай отдельную ветку и worktree от явно выбранной base: `git worktree add -b <branch> <path> <base>`. Не создавай их внутри основного репозитория.
4. Передай исполнителю абсолютный путь worktree, ветку, base и план. Он работает только там, не коммитит, не пушит, не запускает миграции, dev-серверы или тесты с общим состоянием без отдельного разрешения.
5. В отчёте должны быть сделанное, отклонения, проверки, незакрытое и путь worktree. Перед слиянием применяй `/wt-merge`.

Не копируй секреты, `.env`, зависимости и игнорируемые файлы автоматически. Если без них проверка невозможна, сообщи об этом и выбери безопасный способ подготовки окружения.
