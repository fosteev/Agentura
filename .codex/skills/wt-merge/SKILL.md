# Приёмка и слияние worktree

Сначала покажи `git worktree list` и статус каждого известного worktree. Чужие или нераспознанные worktree не меняй. Работающий агент не прерывай и не мержи.

Для готового worktree:

1. Проведи `/plan-review` в его каталоге: diff против плана, DoD и проверки выполняются там. Непринятый результат не коммить и не вливай.
2. Убедись, что ветка worktree чистая; создай коммит только при явной авторизации пользователя или по правилам репозитория.
3. Обнови целевую base безопасным fast-forward. Перебазируй ветку задачи на актуальную base внутри её worktree. Конфликты с разной логикой — стоп и решение пользователя; не угадывай поведение.
4. После rebase повтори проверки из DoD. Вливай fast-forward только когда основное дерево чистое и base является предком ветки задачи.
5. Push, удаление worktree и удаление ветки — отдельные внешние действия: выполняй только при явной авторизации. Не stash и не перезаписывай пользовательские изменения ради слияния.

В отчёте: что принято, какие проверки прошли, конфликты и их решение, что осталось в worktree и почему.
