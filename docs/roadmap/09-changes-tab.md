## Цель

Вкладка правой панели «ход» (таймлайн двух последних ходов) заменяется вкладкой «изменения»: файлы, изменённые
агентом за сессию (или за текущий ход), папками, с +/−, номерами ходов и диффом по клику; ниже — последний прогон
каждой проверки (тесты, линт, типы). То же — во вкладке шапки узкого режима и в свёрнутой полосе.

## Решения (2026-10-03, при планировании)

- **Источник — лента webview, без нового состояния на хосте.** `changesView(rows, opts)` — чистая функция по
  `ChatState.rows` (`src/webview/chatState.ts:143`): номер хода = счётчик строк `kind:'user'` (до первого — ход 1),
  правки — строки `kind:'tool'` с `name` ∈ Edit / MultiEdit / Write и `state` ≠ `err`/`stopped`; путь —
  `input.file_path`; +/− — `editStats(name, input, result)` (`src/webview/toolView.ts:123`), суммой по правкам файла
  (не чистый дифф — так в прототипе; MultiEdit без патча — без цифр). «новый» — первая правка файла в охвате это
  Write с `result.type === 'create'`. Пометку «откат» из прототипа не делаем — её не из чего вывести.
- **Охват: «сессия | ход»** — переключатель вверху вкладки; «ход» = последний ход ленты. Значение хранится в
  `PanelState` (`changes?: 'session' | 'turn'`, по умолчанию `session`). «с коммита», «открыть в SCM», «коммит…» —
  **не в этом этапе** (нужны git / SCM API).
- **Проверки** — Bash-строки, у которых `input.command` похож на проверку: регэксп по словам `test`, `vitest`, `jest`,
  `pytest`, `mocha`, `playwright`, `e2e`, `lint`, `eslint`, `tsc`, `typecheck`, `check`, `cargo test`, `go test`
  (границы слов). Последний прогон каждой команды (ключ — команда после trim), новые сверху, не больше 6. Статус —
  `run` (спиннер, идёт N s) / `ok` (✓, длительность) / `err` (✗, длительность), номер хода. Счётчиков «12 ✓» нет —
  вывод тестов не парсим.
- **Дифф** — новое сообщение webview → хост `{ type: 'diff.changes'; sessionId; toolUseIds: string[] }`. Хост
  (`chatController`) берёт из `this.edits` правки этих id (порядок вставки Map = порядок правок), группирует по
  `filePath`: левая сторона — `before` первой правки файла, правая — `after` последней. Один файл → `deps.openDiff`
  (как сейчас, `stage: 'applied'`, ключ — `changes-<первый id>-<последний id>`); несколько файлов («дифф всего») —
  новый `deps.openChanges(title, files[])` → `DiffDocuments.openChanges` через команду `vscode.changes`
  (multi-diff editor; ресурсы — те же `agentura-diff:` URI, что у `open`). Клик по файлу шлёт id правок этого файла
  в текущем охвате; «дифф всего» — все id охвата. Id без найденной правки пропускаются с `log.warn`.
- **Вкладка переименовывается в коде:** id `'turn'` → `'changes'` (`PanelState.tab`, `Hud.tsx` `Tab`, `Chat.tsx`).
  `readPanel` маппит сохранённое `'turn'` → `'changes'`. Бейдж — число файлов в сессии; `live`, если в последнем
  ходе идёт Edit/Write (`state: 'run'`). Значок в полосе — ± (`<path d="M8 2v6M5 5h6M5 12h6"/>`, как в прототипе).
- **Удаляется** то, что после замены не используется: `TurnPane`, `turnsView`, `timelineView`, `turnBadge`,
  `TimelineView`, строки `ui.turn.*`, их тесты. `.tl` в `media/hud.css` **остаётся** — им пользуется деталь агента
  (`SidePanes.tsx:247`) и тултип. `HudState.turns` и его редьюсер не трогаем (минимальная правка); если после
  удаления вида поле станет мёртвым — отметить в отчёте, не удалять.
- **Правки субагентов** (они не строки основной ленты) в «изменения» не попадают — отдельный вопрос на потом.

## Решения (2026-10-03, по итогам приёмки этапа 1)

- **Номер хода не считает сообщения «в очереди»** (`queued`): иначе отправка сообщения посреди хода открывала пустой
  «ход N+1» и гасила `live`.
- **Проверки — по программе каждой простой команды** (`a && b; c | d`), а не по любому слову в строке: программа —
  `vitest`/`jest`/`pytest`/`mocha`/`eslint`/`tsc`/`playwright test`, либо раннер (`npm`/`pnpm`/`yarn`/`npx`/`go`/
  `cargo`/`make`/`python -m`/`uv run`…) со скриптом, в имени которого `test`/`lint`/`check`/`typecheck`/`e2e`.
  Регэксп ловил `ls test/`, `git commit -m "fix test"`, `grep check`. Фоновые Bash (`run_in_background`) не
  показываются — они кончаются сразу «✓ за 0 с». `stopped` показывается как ✗ (решение исполнителя).
- **Склейка диффа на хосте:** только применённые правки (`proposed` — ещё не изменение); фрагменты (правка без
  исходного файла) с целыми сторонами не сшиваются, идут сами, если целых нет; первая/последняя целая правка файла
  за сессию хранится отдельно (`fileSpans`, `editFiles` в `chatController`) — `MAX_EDITS = 50` вытеснял ранние
  правки, и дифф «за сессию» молча показывал хвост.
- **`DiffDocuments.openChanges`:** все файлы мульти-диффа под одним ключом (`/<ключ>/<i>/before|after/<имя>`) —
  `MAX_PAIRS` не вытесняет документы того же диффа (> 40 файлов), индекс разводит одинаковые имена; ключ — хеш ключей
  файлов. `vscode.changes` колонку не принимает — перед ним фокус группы `editorColumn()`, чтобы не открыть поверх
  чата. Тест — `src/extension/diffDocuments.test.ts` (мок `vscode`).
- Долг: `HudState.turns` и его редьюсер (`hudState.ts`) после удаления таймлайна мёртвые — убрать отдельной правкой.
  `markup.test.ts` сравнивает шапку с `prototype/screens/empty.html` с подменой «ход»→«изменения»: прототипы
  (10 экранов) ещё со вкладкой «ход», правка — у владельца прототипа.
