## Цель

Закрыть замечания дегустации 0.1 и перенести в расширение то, что уже есть в прототипе: правки галереи
v11, прижатый блок «агенты», группу субагентов и карту агентов (A6), вкладку настроек ⚙ и скриншоты в
сообщении (⌘V). Попутно разобрать технический долг из приёмок этапов 3–8 и собрать `.vsix` 0.2.0.
Тег и установку делает владелец.

## Контекст и ограничения

- Код: хост — `src/extension/`, движок — `src/agent/claude/` (`adapter.ts`, `mapper.ts`, `history.ts`),
  протокол — `src/protocol.ts`, webview — Preact/TSX в `src/webview/components/`, строки — `src/webview/strings.ts`.
  В `media/` лежит только CSS (`hud.css`, `webview.css`, `tokens.css`). Эталон вида — `prototype/screens/*.html` и
  `prototype/shared/*.css`, галерея — `prototype/index.html`.
- Проверки: `npm run check` (typecheck + lint + vitest + build), `npm run test:integration` (VS Code ≈ 300 МБ),
  живые сценарии `scripts/*-smoke.mjs` (≈ $0.05–0.10 на прогон), сверка сессий `node scripts/sessions-verify.mjs`
  (нужен `AGENTMETER_DIR`). Юнит-тесты лежат рядом с кодом (`src/**/*.test.ts`), фикстуры — в `test/fixtures/` и
  `src/agent/claude/__fixtures__/`.
- Один репозиторий, поэтому этапы идут строго последовательно.
- Принятое допущение: варианты прототипа A6 (`agents.html`, `agents-done.html`, версия 10), ⚙ настройки и ⌘V
  (`d5e6c13`) берём **как есть**. Явного «принято» от владельца в репо нет: коммит `165f82d` помечен «ждёт выбора».
  Решение вынесено в pending «Решения на подтверждение». Если владелец правит прототип до этапа, правки
  сначала идут в прототип, потом в этап.
- Расхождение с 03-after-0.1.md: `forwardSubagentText` уже `true` (`adapter.ts:295`), решать «включать ли» не нужно.
- Вне этого roadmap (решает владелец, см. «Риски»): вход по API-ключу и ToS, per-platform пакеты со встроенным
  движком, проверка на Windows/Linux, worktree (B9), фичи «Потом» (A13, A14, несколько окон), лимит числа
  живых вкладок.

## Риски и открытые вопросы

- **Варианты прототипа не приняты явно** (A6 «ждёт выбора», ⚙ и ⌘V без пометки). Если владелец захочет
  другое, этапы 2–4 переделываются. Вопрос — в pending «Решения на подтверждение». Ответить до запуска этапа 2.
- **Живое поведение субагентов в SDK** (текущий вызов у foreground, фоновые задачи) может не дать всего, что
  нарисовано. Узнаем в первом пункте этапа 2. Политика: упростить UI, не выдумывать данные.
- **base64 в транскрипте CLI** может не храниться или храниться ссылкой. Тогда в истории будет плашка «скриншот»
  без миниатюры (этап 4, живой прогон).
- **`resumeSessionAt`** может отсутствовать в SDK 0.3.x. Тогда дубль промпта при «Повторить» остаётся и
  документируется (этап 6).
- **CI integration на ubuntu** (VS Code, xvfb) может оказаться флаки. Запасной вариант — integration только по
  ручному запуску (`workflow_dispatch`).
- **Вне скоупа, решает владелец:** вход по API-ключу и ToS до Marketplace; per-platform пакеты; Windows/Linux
  руками; worktree (B9); лимит живых вкладок и усыпление фоновых (каждая вкладка держит процесс `claude`);
  «продолжить диалог» с агентом и таймер кэша субагента; фичи «Потом» (A13, A14, несколько окон).
- Обновление SDK и CLI — отдельным коммитом с прогоном фикстур и `sessions-verify.mjs`. В этом roadmap не планируется.
