# 15 — Codex: решения и ручные проверки

## Решения на подтверждение

- [скоуп] до этапа 5: история Codex-сессий через `thread/list` с фильтром `cwd` (все треды проекта, включая начатые в Codex CLI — паритет с Claude-списком), rename — `thread/name/set`, а не собственный индекс в `workspaceState` из ТЗ — нет второго хранилища, которое разъезжается с реальностью — откат: индекс из ТЗ §5.
- [архитектура] этап 1: открытые вкладки в `workspaceState` (`agentura.openSessions`) хранятся как `{provider, id}[]` вместо `string[]`; старый формат читается как Claude — id без провайдера неоднозначен, когда движков два — откат: писать Claude-ссылки строками (откат на 0.4.0 без этого теряет восстановление вкладок один раз: старый код отбрасывает объекты; упомянуть в CHANGELOG релиза, этап 6).
- [архитектура] этап 1: состояние webview вкладки хранит только `sessionId`, провайдер при восстановлении берётся из памяти воркспейса (нет записи — Claude); `restoredSessionId` уже читает `state.provider`, если этап 3 его добавит — webview этап 1 не трогал — откат: не нужен, добавление поля обратно совместимо.
- [скоуп] этап 2: Stop (`interrupt()`) в Codex-сессии сбрасывает и очередь отправленных сообщений, а не только текущий ход — Stop = «стоп всё», так нет сюрприза, что после Stop агент сам продолжил работу; у Claude следующее сообщение из очереди стартовало бы — откат: убрать `this.queue.length = 0` в `CodexSession.interrupt` (`src/agent/codex/adapter.ts`) и тест «Stop сбрасывает очередь».
- [архитектура] этап 2: тред Codex создаётся лениво — `initialize` при открытии вкладки, `thread/start` только с первым сообщением (resume — сразу); у новой сессии `session.init` приходит перед первым `turn.start`, а не при открытии — пустые треды не засоряют историю Codex (`~/.codex/sessions`) — откат: звать `openThread()` в конструкторе `CodexSession` после handshake для обоих случаев.
- [архитектура] этап 2: до этапа 4 approval-запросы Codex получают явный отказ по схеме (`decline` / пустой grant), а не ошибку `-32601` — `decline` штатно продолжает ход, реакция сервера на ошибку вместо решения не описана схемой (риск зависшего хода); политика пользователя не ослабляется — откат: таблица `REFUSALS` в `adapter.ts` → пустая (всё уйдёт в `-32601`).
- [архитектура] этап 2: у Codex `turn.result.totalCostUsd = 0` означает «неизвестно» (стоимость сервер не сообщает), вложенные файлы (`PromptFile`) отбрасываются с warn — этап 3 обязан спрятать HUD цены и вложение файлов флагами провайдера, иначе в UI будет «$0» и молча потерянный файл — откат: добавить в `AgentEvent` явное «стоимость неизвестна» (`totalCostUsd?: number`) — шире, трогает Claude-путь.
- [архитектура] этап 2: таймаут `thread/start`/`turn/start` (60 с, MCP/хуки пользователя стартуют внутри) закрывает Codex-сессию целиком (`error` + `session.closed`), а не только ход — поздний ответ означает, что тред/ход на сервере уже есть, повтор поверх него дал бы второй тред или ход поверх активного — откат: в `drain()` убрать ветку `isTimeout` (ход закроется ошибкой, сессия жива) и принять риск рассинхрона.
