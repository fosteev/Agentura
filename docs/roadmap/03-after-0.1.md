## Технический долг (из приёмок и рисков)

### Производительность и данные
- [ ] Список сессий во время хода синхронно перечитывает активный `.jsonl` целиком (итоги + `requestExtras`) на потоке хоста не реже раза в 4 с — на сессиях в десятки МБ подвисания. Лечение: разбор по смещению или пропуск итогов живой сессии с `total_cost_usd` движка (этап 6)
- [ ] `transcriptExtras` держит строки файла в памяти целиком на `resume`/пересеве (этап 6)
- [ ] Пересев при идущем ходе может потерять дельты, пришедшие за время чтения транскрипта (редко: «Reload Webviews» посреди ответа) (этап 6)
- [ ] Ход с моделью без цены выпадает из `totalCostUsd` истории без пометки (этап 6)
- [ ] Синтезированный `turn.result` всегда `ok: true` — ошибка API в истории показана отдельной строкой `error` (этап 6)
- [ ] Переименование сессии, у которой идёт ход, может быть перезаписано названием из памяти CLI — не проверялось (этап 6)
- [ ] Формат транскриптов внутренний: фикстуры Agentmeter и сверка `scripts/sessions-verify.mjs` при каждом обновлении CLI/SDK (риск)
- [ ] SDK 0.3.x меняется: версия зафиксирована точно, обновлять отдельным коммитом с прогоном фикстур этапа 0 (риск)

### Разрешения, дифф, ошибки
- [ ] Перезагрузка только webview («Reload Webviews», перенос панели в окно) теряет ленту и ждущие карточки, брокер ждёт ответа: при `ready` пересылать ждущие `*.request` (этап 5; частично закрыто восстановлением сессий в этапе 6 — перепроверить)
- [ ] Относительный `file_path` читается от cwd процесса, а не сессии (движок даёт абсолютные — не встречалось) (этап 5)
- [ ] У нескольких `addRules` с разными `destination` подпись кнопки называет место первого (этап 5)
- [ ] Автосохранение целевого файла перед превью правки: сохранение при показе карточки, до решения; в `acceptEdits`/`bypass` нет карточки и нет сохранения; пути без нормализации регистра (Windows) (этап 7)
- [ ] При оборванном ходе промпт после «Повторить» дважды в транскрипте — убрать можно обрезкой (`resumeSessionAt`, форк) (этап 7)
- [ ] `inflight` помнит один промпт: сообщение, отправленное во время хода и упавшее отдельным ходом, «Повторить» не повторит; карточка может остаться в «повторяю…», если хост пропустил повтор (этап 7)
- [ ] `agentura.debug.showState` видна в палитре всем — скрыть через `when` или `enablement` (этап 7)
- [ ] Строка «порог пройден» в ленте и «сообщение сохранено, уйдёт по кнопке» — отступления этапа 4, решено вместе с состояниями этапа 7 (проверить, что закрыты)
- [ ] Каждая вкладка держит свой процесс `claude` (память); лимит числа живых вкладок/усыпление фоновых (этап 6)
- [ ] Сессии из worktree попадают в список, но `resume`/история идут с `cwd` основной папки и транскрипт не найдут (worktree — B9) (этап 6)
- [ ] `WorkspaceFiles.watch()` без теста (нужен vscode) — покрыть интеграционным тестом (этап 3)

### Упаковка и релиз
- [ ] `.vsix` универсальный и без бинарника движка: нужен системный `claude`. Per-platform пакеты со встроенным движком (`vsce package --target`, 213–224 МБ на платформу) — решить, нужны ли, перед публичной раздачей (этап 8)
- [ ] Проверка `.vsix` только на macOS arm64; Windows/Linux (поиск `claude.exe`, пути, Keychain) — не прогонялись (этап 8)
- [ ] Поиск `claude` при первом запуске движка синхронный (`execFileSync … --version`, таймаут 5 с на кандидата) — на медленном диске/зависшем бинаре держит поток хоста; перевести на асинхронный прогрев при активации (этап 8)
- [ ] Windows: `claude`, поставленный через npm, — это `claude.cmd`, его `execFile` без shell не запустит; поиск знает только `claude.exe` (этап 8)
- [ ] Не нашли `claude` → SDK пробует свой бинарник, которого в `.vsix` нет: кроме предупреждения в ленте будет ошибка движка — проверить текст и, возможно, не запускать движок вовсе (этап 8)
- [ ] CI: `npm run check` + `npm run test:integration` (скачивает VS Code ≈ 300 МБ) (этап 8)
