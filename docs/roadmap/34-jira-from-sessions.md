# Открытие Jira-задачи из списка сессий

Статус: реализовано и принято по коду, тестам и браузерному стенду. Маршрут M, один текущий исполнитель, без делегирования.

Утверждённый эталон: `prototype/screens/jira-from-sessions.html`.

## Скоуп и точки входа

- `src/webview/components/Sidebar.tsx`: плюс заголовка сессий, сейчас сразу session.new.
- `src/extension/sidebarView.ts`: обработка сообщений sidebar.
- `src/extension/taskLink.ts`, `jira/source.ts`, `taskGroups.ts`: разбор ссылки, подключённые источники, уникальный ключ группы instance + issue.
- `src/extension/chatPanel.ts`: открытие/возобновление и контекст нового чата.
- `src/protocol.ts`: строгая проверка запросов.

## План и DoD

1. Типизированный поиск через подключённую Jira: ссылка/ключ; выбор инстанса для неоднозначного ключа; ошибки подключения, доступа, таймаута. Не обращаться к произвольному адресу из ввода.
2. Меню плюса: новый чат без задачи / открыть Jira. Диалог показывает карточку, существующие чаты (включая архивные), новые настройки только при создании.
3. Открыть существующую задачу/чат без новой сессии. Явное создание — через текущий механизм контекста и ту же группу; повторный submit и устаревший ответ не создают дубли. Незапущенная открытая вкладка тоже считается существующей.
4. RU/EN, клавиатура, короткая/узкая панель. Контекст задачи и prompt передаются; из sidebar prompt остаётся в поле, как у текущей команды.
5. Unit/DOM/protocol-тесты на поиск, изоляцию инстансов, ошибки, гонки, повторное открытие/создание. typecheck, lint, build, git diff --check. Визуальный просмотр настоящего компонента в Chrome; живую Jira/установленное расширение не объявлять проверенными без запуска.

Существующие изменения этой сессии в NewChatPopover и переводах сохраняются. Чужие прототипы/конфиг/фикстуры не трогать. Без коммита, push, установки и Jira-записей.
