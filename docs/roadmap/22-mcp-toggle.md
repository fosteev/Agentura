# 22 — Вкл/выкл MCP-сервера из вкладки «mcp» и всплывашки

Продолжение roadmap 21 (`21-skills-mcp.md`, решение 3 отложило вкл/выкл). Владелец выбрал в галерее (раздел
`#mcp-manage`, экран `prototype/screens/mcp-manage.html`) варианты 1 + 2 + 4: тумблер у сервера во вкладке «mcp» и во
всплывашке «mcp N/M», метка источника, состояние «выключен», системная строка в ленте. Меню области (3) и добавление
сервера (5) — не берём. Одна сессия исполнителя + приёмка, релиз 0.15.0.

## Разведка (2026-10-13)

- **Живая проба `toggleMcpServer` (SDK, CLI из `node_modules`)**: `toggleMcpServer('marketplace', false)` → статус
  `disabled` сразу в той же сессии, и в `~/.claude.json` → `projects[<cwd>].disabledMcpServers: ["marketplace"]`. Новая
  сессия в той же папке стартует с `disabled`. `toggleMcpServer(name, true)` убирает имя из списка. Значит, это
  **выключение в проекте (папке чата)**, а не «в этом чате»: действует на все чаты этой папки и на Claude Code в
  терминале. Подписи — «в проекте», не «в этом чате», как было на прототипе.
- **Codex 0.160.0**: в app-server нет вкл/выкл одного сервера (есть только `config/mcpServer/reload`, запись конфига —
  глобально навсегда). Тумблер у Codex скрыт. Antigravity — MCP скрыт целиком, как в 21.
- Эталон всей проводки — «повторить» (`mcp.reconnect`) из 21: протокол → контроллер → адаптер → `refreshMcp`.

## Решения

1. Флаг движка `features.mcpToggle`: Claude `true`, Codex `false`, Antigravity `false`.
2. Сообщение webview→хост `{ type: 'mcp.toggle'; name: string; enabled: boolean }`, валидатор как у `mcp.reconnect`
   (имя 1..128) + `enabled` boolean. Контроллер — только у живой сессии (как `mcp.reconnect`), нет метода — warn в лог.
3. Адаптер Claude `mcpToggle(name, enabled)`: `q.toggleMcpServer`, ошибка — warn в лог; затем `refreshMcp(true)` —
   ответ всегда приходит `mcp.status`. Оптимистичного состояния в webview нет: тумблер показывает статус из
   `mcp.status` (проба: 1–17 мс).
4. Тумблер (`.tg`, вёрстка из прототипа) — у каждого сервера, кроме встроенного (`builtin`, `agentura_jira`: им правит
   настройка Jira). Включён = статус не `disabled`. Показывается и у `failed`/`needs-auth`/`pending` (выключить сломанный —
   частый случай). Кнопка `role="switch"`, `aria-checked`, `data-tip`:
   - вкл → «Выключить {name} в этом проекте: тулы уйдут из контекста со следующего хода. Действует на все чаты этой
     папки и на Claude Code в терминале»;
   - выкл → «Включить {name} в этом проекте».
5. Метка источника — чип `.src` после имени из `McpServerInfo.scope`: `claudeai` → `claude.ai`, остальное как есть
   (`user`, `project`, `local`, `plugin`, `dynamic`…). У `builtin` чипа нет (там уже заметка «встроенный»). Нет `scope` —
   нет чипа. Чип показывается и у Codex, если `scope` пришёл.
6. Выключенный сервер: строка `.srv.off` — имя приглушено, точка `off` (уже есть), заметка «выключен» (уже есть), справа
   вместо тулов — `—`. Счётчик «N/M» не меняем: `mcpCounts` уже не считает `disabled` в M.
7. Системная строка: `mcpNote` получает третий вариант `toggle` — сервер перешёл в `disabled` из любого другого статуса
   (`off`) или из `disabled` в любой другой (`on`). Если в том же событии есть и сбой (`fail`) — приоритет у `fail`,
   как сейчас. Текст:
   - выкл: «MCP: выключен(ы) {имена} в проекте · {N} тул. уйдут из контекста со следующего хода · [вернуть]» — N
     из `tools` прошлого статуса (нет числа — без этой части); «вернуть» шлёт `mcp.toggle enabled: true` по каждому;
   - вкл: «MCP: включён(ы) {имена} в проекте · подключится со следующего хода».
   `noteVisible`: `toggle` виден при `failures` и `start`, скрыт только при `off`. Пересев живой сессии (`mcpQuiet`)
   строку не пишет — как сейчас.
8. Строки — `strings.ts` и `strings.en.ts` (en: «in this project», «retry» уже есть → «undo»/«turn back on» — выбрать
   «undo»). Склонения — существующими хелперами `ui.mcp.tools(n)`, если подходят.
