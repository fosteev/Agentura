# 21 — ручные проверки и решения на подтверждение

Пополняется приёмкой каждого этапа. Отмечает владелец.

## План (2026-10-10) — решения, принятые без обсуждения

- [ ] `agentura.mcp.feedStatus` по умолчанию `failures` (строка только при сбое), а не `start` (сводка при каждом
      старте) — решение 12.
- [ ] «войти» у сервера `needs-auth` — подсказка с командой, не кнопка авторизации (в SDK её нет) — решение 3.
- [ ] Число токенов скилла («3.1k» в прототипе) не показываем — решение 7.
- [ ] Скиллы для Codex не показываем; Antigravity — все отображения скрыты — решения 2, 5.

## Решения на подтверждение

- [ ] [архитектура] этап 1: флаги возможностей MCP (`mcp`, `mcpReconnect`, `mcpReloadAll`, `skills`) — в
      `ProviderFeatures` (`chat.info.features`), а не в `capabilities()`/`session.init` — так устроены остальные флаги
      движков, webview прячет UI по ним без ожидания сессии — откат: перенести четыре поля в `session.init` и читать
      в webview оттуда.
- [ ] [архитектура] этап 1: новое сообщение хост → webview `skill.files {names}` (у каких скиллов найден SKILL.md) —
      решение 6 «не нашёл — ссылки нет» без него невыполнимо: webview не знает про файлы — откат: убрать сообщение и
      signal `skillFiles`, показывать ссылку всегда и молча игнорировать ненайденный файл на хосте.
- [x] [скоуп] этап 1 (владелец 11.10: **плагинным без ссылки** — делает этап 2): «открыть SKILL.md» у плагинного скилла `a:b` открывает `.claude/skills/b/SKILL.md` проекта или
      домашней папки — если у пользователя есть свой скилл `b`, откроется он, а не плагинный (следствие решения 5) —
      откат: брать точный путь из сообщения движка «Base directory for this skill: …» (см. «Риски» roadmap) или не
      давать ссылку плагинным.
- [x] [скоуп] этап 1 (владелец 11.10: **оставить**): у Codex статус MCP запрашивается после открытия треда — в новой вкладке Codex кнопка «mcp» и
      вкладка появятся только после первого сообщения (тред открывается с ним); приёмка закрепила: до треда ↻ и
      «перезапустить все» ничего не делают (без `threadId` Codex поднимает все серверы ради списка) — откат: звать
      `mcpStatus()` при создании сессии (список придёт со статусом `pending` у всех, ценой лишнего запуска серверов).

- [x] [скоуп] этап 2 (владелец 11.10: **оставить**): строка «X отключился» — при переходе в `failed`/`needs-auth` из любого состояния, а не только из
      `connected`; в пределах хода, где пришла сводка старта с `pending`, статус переписывает эту сводку («X не
      подключился»), а не добавляет строку — init Claude даёт `pending`, и без этого сбой при подключении был бы без
      строки или «отключился» про сервер, который не поднимался — откат: в `mcpNote` считать сбоем только переход из
      `connected`, убрать `settlingStart`.
- [x] [скоуп] этап 2 (владелец 11.10: **оставить**): `/имя` скилла, набранное пользователем, полосой в ленте не рисуется (это текст промпта, вызова
      `Skill` нет) — учитывается только в «скиллах сессии» этапа 3 — откат: рисовать `SkillRow` «вызван вами» под
      репликой пользователя по `slashSkill`.
- [ ] [архитектура] этап 2: счётчики вызовов и скиллы сессии не хранятся в `ChatState`, а считаются по `rows`
      (`mcpUsage`/`sessionSkills`); системная строка — обычный `sys` с полем `mcp` в ленте, её показ решает
      `feedStatus` при рендере; пересев помечается полем протокола `session.history.mcpReplay` — откат: хранить
      счётчики в `ChatState` и пересчитывать в `seedHistory`, строку фильтровать при записи.
- [x] [скоуп] этап 3 (владелец 12.10: **оставить**): кнопка «mcp N/M» и вкладка «mcp» скрыты и при пустом списке серверов (`servers: []`), а не только
      до первого статуса — «mcp 0/0» ничего не говорит, а у сессии без серверов вкладка была бы пустой — откат: в
      `mcpSurfaceShown` (`src/webview/mcpView.ts`) убрать `servers.length > 0`.

## Проверить руками

- [ ] Этап 1 (UI — этап 3). Codex с настроенными MCP-серверами (`~/.codex/config.toml`):
      открыть вкладку Codex, отправить сообщение, открыть «mcp N/M». Увидеть: все серверы из конфига, статусы
      «подключён/ошибка/ждёт входа» правдоподобны, у подключённых есть версия (при `toolsAndAuthOnly` её могло не
      быть) и число тулов; ни один сервер не висит «ожидает» дольше запуска (`runtimeStatus: null`). «Перезапустить
      все» — статусы проходят через «ожидает» и возвращаются.
- [ ] Этап 1 (UI — этап 3). Claude: вкладка с сервером, который падает (например, stdio с несуществующей командой):
      «mcp» показывает его «ошибка» с текстом; «повторить» шлёт переподключение, статус обновляется. Включить и
      выключить все три статусных отображения в настройках посреди сессии — после следующего хода статус обновляется
      только когда хотя бы одно включено (Output → Agentura без предупреждений `mcpServerStatus`).
- [ ] Этап 2. Claude, вкладка с MCP-вызовами и скиллом (например, `serena` и `/plan`-подобный вызов `Skill` агентом).
      Переключить `agentura.feed.style` на journal, folded, replies, cards, в светлой и тёмной теме. Увидеть: у
      MCP-вызова op `mcp` и чип сервера с исходным именем (`claude.ai Gmail`, не `claude_ai_Gmail`); вызов `Skill` —
      полоса «◆ скилл <имя> · вызвал агент», у своего скилла есть «открыть SKILL.md» (открывает файл), у плагинного
      `a:b` ссылки нет; в итоге хода `mcp N`/`скилл N`; в folded свёрнутый ход показывает «mcp ×N» и полосу скилла,
      а ход без скилла не получает лишнего зазора; в replies чипы в ряду инструментов, полоса на всю ширину.
- [ ] Этап 2. Сервер, который не поднимается (stdio с несуществующей командой). Новая вкладка, отправить сообщение.
      `feedStatus=failures`: одна строка «MCP: N подключён(ы) · X не подключился (ошибка)» в ходе этой реплики, без
      «отключился»; клик «список» раскрывает серверы. `start`: та же одна строка, раскрыта. `off`: строки нет.
      Перезагрузить webview (Developer: Reload Webviews) — новой строки в конце ленты нет. Чип вызова к упавшему
      серверу (если он был) — красный.
- [ ] Этап 2. `agentura.mcp.feedLabels = false`: лента как до 0.11 — короткие имена тулов, `Skill` обычной строкой,
      без чипов и счётчиков.
- [ ] Этап 3. Кнопка у поля. В Claude-вкладке с MCP-серверами переключить `agentura.composer.layout` по всем шести
      раскладкам, ширина панели узкая (~380 px) и широкая, светлая и тёмная
      тема. Увидеть: «mcp N/M» рядом с «rc», жёлтая точка при сбое; всплывашка открывается вверх, целиком в окне (не
      уходит за левый/правый край), прокручивается при длинном списке; клик вне и Escape закрывают её, второй Escape
      останавливает ход как раньше; ↻ обновляет статус. У `needs-auth` — подсказка входа, «скопировать команду» кладёт
      `/mcp` (Codex — `codex mcp login <имя>`) в буфер, подпись на секунду меняется на «скопировано».
- [ ] Этап 3. Вкладка «mcp» правой панели: четвёртая, после «агенты»; бейдж жёлтый с числом сбоев; иконка в рейле

      скиллы…» раскрывает список имён. Выключить `agentura.mcp.panelTab` при открытой вкладке «mcp» — панель переходит
