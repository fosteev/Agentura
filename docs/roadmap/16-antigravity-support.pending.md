# 16 — Antigravity: на подтверждение и ручные проверки

## Решения на подтверждение

- [ ] `[скоуп]` Режим `default` в agy = авто-отказ (agy не умеет спрашивать по действию). В ленте —
      карточка «agy отклонил: X» с кнопками «Разрешить правки и повторить» / «Разрешить всё и
      повторить». Альтернатива — новые Antigravity-сессии сразу в `acceptEdits`. До этапа 4.
- [ ] `[скоуп]` Имя провайдера в UI — «Antigravity» (внутри agy есть и Claude/GPT, не только Gemini).
- [ ] `[скоуп]` Модель по умолчанию для Antigravity-сессий без выбора — `gemini-3.8-flash-medium`
      (`DEFAULT_AGY_MODEL` в `src/agent/antigravity/models.ts`). Альтернатива: `-low` (дешевле по квоте) или `-high`.

- [ ] `[скоуп]` этап 2: служебный повтор после отказа («Retry…») идёт без пузыря пользователя в ленте
      (`turn.start` без `prompt`), а режим после «Разрешить правки/всё и повторить» остаётся повышенным до смены
      пользователем. Альтернатива — показывать реплику повтора и/или возвращать режим после хода.
- [ ] `[архитектура]` этап 2: диффы правок берутся из недокументированного `transcript_full.jsonl` (хвост файла,
      шаг стрима N = GENERIC N, вызов — в ближайшем planner-шаге), подгрузка асинхронная через «гейт» сессии: события
      после правки ждут до 2 с. Повтор после отказа — `retryWithMode` вне общего `AgentSession` (`isAgySession`), нового
      `AgentEvent` нет. Откат: убрать `editResults` в `adapter.ts` — карточки правок без диффа, гейт простаивает.
- [ ] `[архитектура]` этап 1: процесс `agy` поднимается сразу при создании/resume сессии (а не к первому
      сообщению) и живёт до dispose — `init` (id беседы, модель) приходит до ввода, Stop/смена модели
      пересоздают его лениво с `--conversation`. Цена: каждая открытая вкладка Antigravity держит процесс agy
      (на этапе 4 — и восстановленные после перезагрузки окна). Откат: в `AgySession` спавнить в `ensureProc`
      к первому `send` (id сессии тогда пуст до первого хода).
- [ ] `[архитектура]` этап 1: kill дерева — снимок потомков по `ppid` от pid нашего agy (`ps -A -o pid=,ppid=`)
      до SIGINT/закрытия stdin, перед SIGKILL — второй снимок от уже снятых потомков; по имени/шаблону не
      убиваем, от pid agy после его выхода не ищем. Не ловятся: новые прямые дети agy после первого снимка,
      уже переподвешенные к pid 1 до него (фоновые хвосты прошлых `run_command`) и потомки agy, умершего
      посреди хода; теоретическая гонка переиспользования pid в окне ≤2,5 с. Откат/
      усиление: сверять `lstart` pid перед SIGKILL или запускать agy в своей группе и бить `-pgid`.
- [ ] `[скоуп]` этап 3: в запасной индекс Agentura (`globalState`, ключ `agentura.antigravity.sessions`) пишется первое
      сообщение беседы (≤300 символов) — заголовок списка, когда `node:sqlite` недоступен; копия текста переписки хранится
      локально в состоянии расширения — потому что иначе запасной список был бы из одних id — откат: убрать `firstPrompt`
      из `AgySessionIndex.note` (заголовок запасного списка — id).
- [ ] `[архитектура]` этап 3: список бесед — недокументированная `conversation_summaries.db` agy через `node:sqlite`
      (есть в Node ≥22.13; VS Code `^1.100` на Node 20 и форки его не имеют), чтение по копии с `-wal`/`-shm` в `mkdtemp`,
      кэш по размеру/mtime, сбой — прошлый список; запасной путь — собственный индекс бесед, начатых/продолженных из
      Agentura (беседы из терминала там не видны). История — `transcript_full.jsonl` (>32 МБ — хвост). Имена (rename) —
      только у Agentura, в agy и других клиентах не видны — потому что у agy нет API и `~/.gemini` не пишем — откат:
      `readConversationSummaries` → `undefined` (только индекс), либо убрать индекс и показывать только базу.

- [ ] `[скоуп]` этап 4: в agy-чате `metrics: false` (нет кольца контекста, кэша, лимитов Claude, стоимости); `default` для
      новых agy-сессий берётся из `agentura.defaultPermissionMode` (по умолчанию «по запросу» = авто-отказ + карточка);
      карточка отказа не восстанавливается после перезагрузки вкладки (только живой ход); сайдбар с беседами agy перенесён в
      этап 5 (ждёт этап 5 Codex). Откат/альтернатива — см. «Решения … сессии 4» в roadmap.

- [ ] `[архитектура]` этап 4 (приёмка): `ChatController` обновляет `lastInit.permissionMode` на `mode.changed` у всех
      провайдеров, не только agy — потому что пересев webview пересылал режим начала сессии, и после повтора agy в «всё
      разрешено» меню показывало бы «по запросу» (у Claude/Codex то же расхождение после смены режима + Reload Webviews) —
      откат: условие `this.engineProvider === 'antigravity'` в ветке `case 'mode.changed'` `onEvent`.

- [ ] `[скоуп]` этап 5: квота agy показывается в HUD вкладки Antigravity (у поля ввода, `Gemini 74%` = израсходовано),
      а не в сайдбаре; сайдбар с беседами agy не сделан (блокер: этап 5 Codex в main). Откат: убрать ветку `quota` в
      `Meters` (`Composer.tsx`) — квота просто не рисуется.
- [ ] `[скоуп]` этап 5: «Движок новых чатов» (`defaultProvider`) и путь к agy добавлены в ⚙ → «Движок»; пути Codex в
      карточке по-прежнему нет.

- [ ] `[архитектура]` этап 5: квота agy — отдельное сообщение `quota.update` и сервис `AgyQuotaService` (один на
      расширение), а не окна в `limits.update`/`LimitsSource` — лимиты Claude общие на аккаунт и затирали бы окна agy в
      сторе. Откат: убрать `quota.update` и `agyQuota` из `ChatDeps` — agy-вкладки снова без приборов.
- [ ] `[скоуп]` этап 5: в HUD квота показывается **израсходованной** (`Gemini 74%` при «Weekly Limit Remaining 26%» у agy) —
      как лимиты Claude, чтобы цвет уровня работал одинаково; остаток — только в подсказке. Если путает — откат:
      `percent: r.remaining` в `quotaView` (`hudView.ts`) и пороги цвета перевернуть.
- [ ] `[архитектура]` этап 6: беседы agy в списке сессий — через то же состояние чтения, что у Codex (`ExtraState` на
      провайдера в `SessionsService`: кэш 30 с, бэкофф 60 с, одно чтение за раз, `rev` после rename; `LiveSessions.epochOf`)
      — вместо параллельной копии для третьего движка; поведение Codex прежнее, его тесты не менялись. Откат — revert
      коммита этапа 6 (список снова Claude + Codex).
- [ ] `[архитектура]` этап 6 (приёмка): списки сайдбара проверяют движок тихой пробой `EngineLocator.available()` — «не
      найден» не пишется в журнал (раньше у Codex: warn каждому без `codex` при первом показе сайдбара и info на каждое
      перечитывание; у agy так же вернулось бы предупреждение, убранное на приёмке этапа 4). Запуск сессии предупреждает как
      раньше. Касается и Codex. Откат: в `extension.ts` вернуть `available: async () => (await xEngine.ready()).ok`.
