# 29 — Cursor: решения и ручные проверки

## Решения на подтверждение

- [архитектура] этап 1: транспорт jsonrpc 2.0, ответ разрешения `{outcome:{outcome:selected, optionId}}`, режим `session/set_mode`, модель `session/set_config_option`, список `session/list` — так ответил живой CLI, на этом этапы 2–4 — откат до кода адаптера бесплатный, после этапа 2 это переписка клиента.
- [скоуп] этап 1: флаг questions не поднимать — кадра `cursor/ask_question` не было, карточек вопросов в v1 не будет — откат: поменять промт 5, когда кадр появится.
- [скоуп] этап 1: `sessionUpdate` `plan` с `entries` в ленту не выводить — кадр был один, карточка плана остаётся на `cursor/create_plan` — откат: замапить entries на этапе 3.
- [архитектура] этап 2: штамп CLI — регекс `YYYY.MM.DD-<hex>`, не пин `2026.11.05-86047df` — следующая сборка иначе стала бы «не найден» — откат: сравнивать с `CURSOR_FIXTURE_CLI` в `parseCursorVersion`.
- [скоуп] этап 3: `providerFeatures('cursor').plan` поднят в true (`cursor/create_plan` есть карточка). `questions` остаётся false. Откат: `plan: false` в `CURSOR_FEATURES`.
- [скоуп] этап 3: пока идёт `session/load`, permission и plan отвечаются отказом без события — resume не виснет и не рисует историю как живой ход — откат: убрать проверку `loading` в `onPermission` и `onPlan`.
- [скоуп] этап 2: флажок «Cursor» в «Чьи лимиты» уже виден, список идёт из `PROVIDERS` — меню композера и строка пути не добавлены — откат: не рисовать `cursor` в `Settings.tsx` до этапа 5.
- [скоуп] этап 2: `defaultProvider: cursor` в настройках VS Code открывает вкладку с меткой cursor, адаптером Claude и флагами Cursor — enum требовал этап 2, `adapterOf` ещё без ветки — откат: пока нет адаптера считать это значение как `claude`.
- [скоуп] этап 4: `loadHistory` игнорирует `stopBefore` — у кадра `session/update` нет id сообщения, «Повторить ход» не отрежет промпт — откат не нужен, обрезки нет; появится id — резать в `buildCursorHistory`.
- [скоуп] этап 4: заголовок строки списка — `sessionId`, `session_info_update.title` в список не подмешивается — `session/list` title не отдаёт, load на каждую строку не делали — откат: писать title в `sessionsFrom`, когда список начнёт его присылать.
- [скоуп] этап 4: permission и plan посреди короткого `session/load` в ленту истории не кладутся — клиент закрывает запрос сам, карточка была бы без живой сессии, в повторе спайка этих запросов нет — откат: на время load прокинуть маппер карточек в короткий `acp`.
- [скоуп] этап 5: всплывашка нового чата задачи и `/new cursor` принимают cursor — иначе `task.newChat` с этим провайдером молча отбрасывался; у Codex и Antigravity пункт уже был, этап называл пустую вкладку — откат: убрать `cursor` из `ENGINES`, `parseNewCommand` и проверки `task.newChat`.
- [архитектура] этап 5: режимы новой сессии берутся из `providerFeatures().modes`, а не из `claude || antigravity` — у Cursor флаг true, у Codex false, три старых движка остаются на прежней ветке; модель и effort Claude в Cursor не передаются — откат: вернуть `hasModes = claude || agy`, Cursor снова стартует без режимов настроек.

- этап 1: чаты спайка остались в аккаунте Cursor (`session/delete` в протоколе нет). Удалить в UI, если мешают.
- этап 2: сессия smoke `6a4f9cf5-a9d3-4620-89b9-eb4fb20762b0` осталась в аккаунте Cursor. Удалить в UI, если мешает.
- этап 2: Windows — `agent.cmd` / `agent.bat` не принимаются. Живьём не гонялось.

- этап 4: сайдбар после подключения (этап 5) — строка сессии называется `sessionId`, не title из Cursor. Живой `session/list` этим этапом не гонялся.
