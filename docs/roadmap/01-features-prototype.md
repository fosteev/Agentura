# Agentura: от каталога фич до зафиксированного прототипа

> Статус: в работе · 2026-09-30
> Исполнитель отмечает чекбоксы по ходу работы — по факту проверки, не «вроде сделал».

## Цель

В репозитории лежат согласованный список фич (`docs/features.md`) и зафиксированный
HTML-прототип интерфейса (`prototype/`), по которым можно начинать реализацию
расширения без возврата к обсуждению «что строим и как оно выглядит».

## Контекст и ограничения

- **Что строим.** Расширение VS Code — единый интерфейс для ИИ-агентов с приборами,
  которых нет в официальных клиентах. Старт с Claude.
- **Архитектура (решено).** Схема официального расширения: код на стороне VS Code
  запускает движок агента и пересылает сообщения, чат — веб-страница в webview.
  Claude подключается через Claude Agent SDK (движок — бинарник `claude`).
  Граница адаптера кроится по форме ACP (Agent Client Protocol), чтобы Codex и
  Gemini подключались позже без переделки интерфейса. Полный ACP-клиент — не цель.
- **База.** `docs/feature-inventory.md` — каталог фич официального расширения
  Claude Code 2.1.284 (20 разделов, около 150 фич, списки команд, настроек и хоткеев).
  В нём есть раздел «Не подтверждено» — на эти пункты не опираться как на факт.
- **Прототип — статический HTML/CSS/JS без сборки**, в `prototype/`. Webview — это
  веб-страница, поэтому зафиксированный прототип становится основой вёрстки.
- **Не в этом плане:** код расширения, выбор сборщика, публикация в Marketplace.
  Реализация планируется отдельным roadmap после этапа 3.
- **Допущение:** данные для приборов (токены, стоимость, лимиты, кэш) доступны из
  сообщений SDK и служебных запросов к движку. Проверяется на этапе реализации;
  в `features.md` источник данных каждой своей фичи помечен как допущение.

## Риски и открытые вопросы

- **«Визуально интереснее» не определено.** Узнаем на этапе 2.1: три направления вместо
  спора на словах. Если ни одно не попадёт — ещё один заход 2.1, а не переход к 2.2.
- **Данные для приборов — допущение.** Если SDK не отдаёт лимиты или фактические цифры
  кэша, фичи A3 и A4 уедут в «Потом» или будут считаться из транскриптов (как в Agentmeter).
  Проверка — этап 4, до начала реализации.
- **Каталог содержит строки из кода чужого расширения.** Перед тем как делать репозиторий
  публичным, `docs/feature-inventory.md` нужно пересмотреть: оставить описание поведения,
  убрать дословные фрагменты кода.
- **Имя `agentura` занято на npm** (пакет другой тематики) и небольшим проектом на GitHub.
  На идентификатор расширения в Marketplace это не влияет; если понадобится npm-пакет —
  нужен scope или другое имя пакета.
- **Вопрос владельцу:** правки к меткам в `features.md` после этапа 1.
