# Фичи Agentura

Список фич будущего расширения Agentura: паритет с официальным расширением Claude Code 2.1.284 (по `docs/feature-inventory.md`) и свои фичи.
Метки: MVP — входит в первую версию; Потом — после MVP; Нет — не делаем. Спорные метки разобраны на приёмке 2026-09-30; прототип утверждён владельцем 30.09.2026 (тег `prototype-v1`), список приведён к нему: B1 «чат в боковой панели» → Нет, A10 → MVP (частично), добавлены A14, A15.

## Статус MVP (на конец этапа 7, 2026-10-01)

Аудит строк с меткой MVP по коду (grep по именам, настройкам, командам, наличию тестов) — не вживую. Сделаны все строки A1–A8, A10, A14 (только подпись), A15 и MVP-строки таблиц B, кроме двух отступлений: строка «коммит» в A15 перенесена в «Потом» (см. A15), а процент контекста и сортировки в списке сессий (A10) — «Потом» по прототипу. Построчные пометки «сделано на этапе N» стоят там, где этап оставил решение или оговорку; остальные строки — без пометки, значит «сделано по описанию». На глаз (F5) владелец ещё не проверял: этапы 3–7 принимались по тестам и живым прогонам движка.

## Принцип MVP

Принцип MVP: в Agentura можно провести обычный рабочий день с Claude, не открывая официальное расширение — написать запрос, видеть ход работы, подтверждать действия, смотреть диффы, вести и возобновлять сессии. Всё, что движок (бинарник claude) делает сам без интерфейса — скиллы, хуки, MCP, память, CLAUDE.md — работает из коробки и отдельного экрана управления в MVP не получает.

## A. Свои фичи

| ID | Фича | Что видит пользователь | Метка | Источник данных (допущение; «Проверено» — по `docs/spikes/sdk-probe.md`) |
|---|---|---|---|---|
| A1 | Шкала контекста в токенах | Всегда на виду рядом с полем ввода: «87k / 200k», размер окна, цвет по порогам пользователя (настройка, по умолчанию 120k / 150k / 200k). Не прячется при малом заполнении | MVP | Проверено: `getContextUsage()` → `totalTokens / maxTokens` (окно 1M на Sonnet 5.5 и Opus 5.5, автосжатие на 967k); между вызовами — `input + cache_read + cache_creation` из usage последнего `assistant` главного цикла. `assistant.context_usage` не приходит |
| A2 | Итог хода | Под каждым ответом: токены (ввод, вывод, чтение и запись кэша), стоимость, длительность | MVP | Проверено: `result.usage` (токены хода), `result.duration_ms`; стоимость хода — разность `total_cost_usd` соседних `result`. Вывод на лету — `message_delta.usage.output_tokens` (в `assistant` плейсхолдер), usage считать один раз на `message.id`. Прерванный ход в стоимость не попадает |
| A3 | Кэш с фактом | Таймер до истечения кэша плюс доля попаданий за сессию | MVP | Проверено: доля попаданий — `cache_read / (input + cache_read + cache_creation)` по `assistant.message.usage`. События истечения нет — таймер свой: `timestamp` последнего ответа + TTL (главный разговор пишет `ephemeral_1h`, субагенты — `ephemeral_5m`) |
| A4 | Лимиты подписки на виду | 5-часовое и недельное окно: полоса, процент, время сброса | MVP | Проверено: `rate_limit_event.rate_limit_info.unifiedWindows.{five_hour, seven_day}` — доля 0…1 и сброс в unix-секундах (поля нет в типах SDK). До первого хода и как запас — `GET /api/oauth/usage` (`limits[]`: `session`, `weekly_all`, `weekly_scoped` по модели), не чаще раза в 15 мин |
| A5 | Таймлайн хода | Лента инструментов по времени: что агент читал, правил, запускал и сколько это заняло | MVP | Проверено: `assistant` с блоком `tool_use` и `user` с `tool_result` + `tool_use_result`; длительность — разность их `timestamp` (отдельного поля нет); у субагентов — `task_progress.usage.duration_ms` |
| A6 | Карта агентов панелью | Дерево субагентов и фоновых задач со статусом, токенами и остановкой — постоянная панель, а не модальное окно | MVP | Проверено: `task_started / task_progress / task_updated / task_notification` и `background_tasks_changed`; сообщения субагента — по `parent_tool_use_id`; токены — `usage.total_tokens`; остановка — `stopTask(task_id)`. Субагент без `run_in_background` стартует фоновым |
| A7 | Переключатель агента | Место в интерфейсе под выбор агента. В MVP доступен только Claude, остальные показаны как «скоро» | MVP | — |
| A8 | Свой визуальный характер | Собственная вёрстка, типографика и тема поверх переменных VS Code; определяется на этапе прототипа | MVP | — |
| A9 | Что в контексте | Разбивка окна по категориям (система, инструменты, MCP, память, сообщения) с весом в токенах — панелью, а не модальным диалогом | Потом | данные команды /context |
| A10 | Обзор сессий | Список сессий с токенами, процентом контекста, стоимостью и статусом каждой | MVP (частично) | Проверено: список — `listSessions({dir})` (название, первый промпт, время; без токенов, ходов и стоимости); токены и ходы — `getSessionMessages()` (`message.usage`, один раз на `message.id`); стоимость есть только в `result` живой сессии (при `resume` копится) — последнее значение хранить на стороне расширения. По прототипу (30.09): в списке сессий боковой панели показаны ходы, стоимость, токены и статус (работа / ждёт ответа / ошибка / лимит); процент контекста и сортировки — Потом |
| A11 | Журнал разрешений | Что было одобрено и отклонено за сессию | Потом | control_request в потоке SDK |
| A12 | Динамика лимитов | График расхода лимита по времени | Потом | rate_limits, накопление на стороне расширения |
| A13 | Другие агенты | Codex, Gemini и прочие через адаптеры по форме ACP | Потом | — |
| A14 | Отложенная отправка при лимите | Когда 5-часовое окно исчерпано: сообщение остаётся в поле, кнопка «отправить в HH:MM автоматически» после сброса | Потом | rate_limits движка (время сброса). В прототипе кнопка нарисована (экран `limit`); в MVP — только подпись «отправка отложена до HH:MM», без автоматики (сделано на этапе 7: баннер, строка «ход не начат», поле ввода `off`; блокировка общая на аккаунт и снимается сама по времени сброса) |
| A15 | Системные строки в ленте | Строки без карточки: компакция контекста (было → стало), коммит, смена режима, решение по плану, ход не начат из-за лимита | MVP (без строки «коммит» — перенесено в «Потом»: нужен разбор вывода `git commit` из Bash, в 0.1 коммит виден строкой инструмента) | result / system сообщения SDK, события расширения. Сделано на этапе 7: компакция (идёт / итог «было → стало»), «ход не начат» с временем сброса, повтор запроса движком одной строкой |

## Вопросы к владельцу

Метки расставлены по правилам архитектора. Ниже — решения, которые зависят от привычек
работы и которые стоит подтвердить или поменять:

- **Очередь сообщений во время работы — Потом.** Если привык писать агенту вдогонку, пока он занят, переносим в MVP.
- **Вставка изображений и скриншотов — после 0.1** (решение владельца 01.10: прототип `image`, пункт в `docs/roadmap/03-after-0.1.md`).
- **Правка диффа по отдельным изменениям — Потом.** В MVP правка принимается или отклоняется целиком.
- **Комментарии к плану — Потом.** В MVP план можно принять, отклонить или попросить доработать текстом.
- **Rewind (откат к чекпоинту) — Потом.**
- **Голосовой ввод, терминальный режим, облачные сессии — Нет.**
- **Раздел A.** Состав своих фич и что из них в MVP: чего не хватает, что лишнее.
