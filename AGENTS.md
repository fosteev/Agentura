# Рабочие правила

Отвечай кратко и технически точно. Не поддакивай: если решение или постановка слабые — скажи прямо.

- Перед правками читай `AGENTS.md`, `CLAUDE.md` и релевантный README проекта. Локальные правила приоритетнее.
- Сначала докажи актуальный путь поиском и чтением файлов, потом правь. Изменения минимальны: без рефакторинга и форматирования вне задачи.
- Не спрашивай о мелочах; останавливайся только при смене скоупа, риске потери данных или необратимом действии.
- Длинный вывод сборок, тестов и `git diff` сохраняй во временный лог; в контекст — только ошибки и нужный фрагмент. Длинные файлы читай частями.
- Для маленькой ясной задачи (до часа, до трёх файлов) работай сразу. Планирование и roadmap нужны только для действительно крупных задач или по прямой просьбе.
- Проверяй результат командами из DoD. Визуальные проверки браузером не запускай ради ритуала: оставляй пользователю короткий чеклист, если без ручной проверки нельзя.
- Не добавляй в коммиты подписи ассистента. Коммит и push — только когда этого требует пользователь или правила репозитория.

Для задач больше часа используй `.codex/WORKFLOW.md` и подходящий скилл из `.codex/skills`.
